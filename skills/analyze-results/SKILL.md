# Analyze Results — 双通道结果分析

目标：模拟一名有经验的无人机研究者看完一次实验后会得出的结论——不只读指标，还要"看"画面。输入是一个实验目录 `experiments/$EXP_ID/`。

## 通道一：数据（先定量）

优先通过 rosbags-mcp 工具查询 bag（若已接入），否则用 `ros2 bag` + Python(rosbags 库) 兜底：

1. **完整性**：`bag_info` — 话题齐不齐？时长对不对？有没有断流？
2. **轨迹**：`analyze_trajectory` — 水平路径 vs 期望方框；每个转角处超调量；垂直通道漂移；
3. **时序**：`plot_timeseries` — 位置误差曲线、速度曲线是否平滑、有无持续振荡（等幅振荡=调参问题，发散=不稳定）;
4. **姿态**：roll/pitch 峰值是否异常大（>30° 对方框任务即异常）；
5. **汇总 metrics.json** 与上述观察互相印证，矛盾之处必须显式指出。

## 通道二：视觉（后定性）

1. 读 `views/*.png` 截图序列（你是多模态模型，直接 Read 图片文件）：
   - RViz：轨迹形状是否规整、TF 树是否正常、有无坐标系跳变痕迹；
   - Gazebo：机身姿态是否自然、有无穿模/触地、场景光照是否影响了机载相机视角;
2. 若 bag 内含图像话题，用 `get_image_at_time` 抽取关键帧（起飞/各转角/降落）一并查看；
3. 视觉与数据矛盾时（如数据显示无超调但截图见明显侧倾）：以数据为准修正结论，并在报告中记录该矛盾。

## 失败分类学（诊断必须落到其中一类，可多选）

| 代号 | 名称 | 典型证据 |
|---|---|---|
| F1 | 定位漂移 | 轨迹末端偏移随时间累积；GPS-denied 场景重点查 |
| F2 | 控制超调/振荡 | 转角过冲、等幅振荡、速度曲线锯齿 |
| F3 | 状态估计跳变 | 位姿阶跃、TF 断裂重连 |
| F4 | 任务逻辑错误 | 航点顺序错、未达点即切下一航段 |
| F5 | 环境/仿真问题 | 穿模、物理失真、传感器噪声缺失 |
| F6 | 配置不当 | 速度上限过高、增益不适配本次负载 |

## 输出：diagnosis_report.md

严格按 `templates/diagnosis_report.md` 结构写入实验目录，核心三段：

1. **一句话结论**（如："任务完成，但第 3 转角存在 0.8m 超调，属 F2 控制超调"）；
2. **证据表**：每条结论附数据引用（话题+时间窗）或图片文件名——禁止无证据断言；
3. **下一步建议**：给出可执行的配置修改（Hydra key=value）或进一步实验建议，供 `iterate-experiment` 直接消费。

## 诚实性红线

- 不确定就说不确定，标注置信度（高/中/低）；
- 只基于本次产物下结论，不脑补未录制的传感器行为；
- 引用数字必须来自 bag/metrics.json 实测，禁止四舍五入到"看起来合理"。
